# エフェクトメモ(ジニーとひょうたん)

スタイルから独立した、動きと形の部品。塗りや影は現在のスタイルの `surface` を使う。

## 部品

| 部品 | 内容 | 参照実装 |
|---|---|---|
| `Modifier.genie(progress, target)` | 進行度(0 開いた形、1 消えた形)から、中身の切り抜きと変形を作る | `page-rail.js` の `genieFrames` / `outline` |
| `GenieSurfaceShape(progress, target)` | 変形したあとの輪郭。面をこの形で縮めずに描くと、線が変形に沿う | なし |
| `GenieVisibility(visible, anchor, surface)` | どの要素にも付けられる出し入れ。`Modifier.genieAnchor(anchor)` を付けた要素に吸い込まれる。`surface`(既定 `Card`)の面を変形に沿わせて描く | 同上 |
| `GourdShape(n, orientation)` | 丸が n 個のひょうたんの形(縦か横) | `rail-shape.js` の `gourdRight` |
| `GourdTabRail(orientation)` | ひょうたん型のタブ(単体)。`Orientation.Vertical`(既定)か `Horizontal` | `.page-rail` |
| `GourdRailPanel(side, railAlignment)` | ひょうたん + パネル + 継ぎ目の変形 + ジニー。表示中のタブをもう一度押すと開閉。`side` でひょうたんをパネルの左(既定)・右・上・下に置き、`railAlignment` で辺のどこに寄せるかを決める | `page-rail.js` の `setClosed` |

## ジニー

| 区切り | 輪郭(a / b / c / d) | 角の丸み(r1 / r2) | 横の移動 | 横の縮み | 不透明度 |
|---|---|---|---|---|---|
| 0 | 0 / 0 / h / h | r / r | 0 | 1 | 1 |
| .5 | 行き先へ .9 / .45 / .45 / .9 | 0 / r/2 | .45 倍 | .55 | 1 |
| .8 | - | - | - | - | 1 |
| 1 | 行き先 ±首(16dp) | 0 / 0 | 行き先 | .02 | 0 |

- 時間 340ms、イージング `cubic-bezier(.45, 0, .8, .4)`(`genie.*`)
- 時間を直線で動かし、イージングをかけてから区切りの間を直線でつなぐ(WAAPI の `easing` と同じ)。開くときは同じ値を逆にたどる
- 行き先がパネルの右にあるときは、左右を反転する(参照実装は左だけ)
- 行き先がパネルの上下にあるときは、縦に縮める(縦横を入れ替えて同じ計算をする)。どちらに縮めるかは、行き先が要素の外へはみ出している量の大きいほう
- メッシュ変形や AGSL は使わない。中身は `graphicsLayer` の `shape` + `clip`、`scaleX`、`translationX`、`transformOrigin` だけ
- 面は層にかけない。変形後の輪郭(`GenieFrame.placedPath`)を計算して縮めずに描く(線の太さが変わらず、中身の切り抜きと縁が一致する)
- 角は円弧の近似(進行度 0 で角丸の四角と同じ形)
- 出し入れの間は、吸い込まれる先の形をくり抜いて面と中身を描く(ボタンの前に出ないように)
- くり抜く位置と形は、Piyo の部品なら見た目を使う。部品が `genieAnchor` に見た目の位置と形を知らせる(`reportGenieAnchor`)。ボタンとチップはタッチ範囲(48dp)の内側の見た目、タブ(`PiyoTabs`)は丸い棒、ひょうたん(`GourdTabRail`)はひょうたんの形。見た目が付けた要素の真ん中にないとき(入れ物に付けたときなど)や、Piyo 以外の要素では、付けた要素の大きさと、`shape`(既定は円)を使う

## ひょうたん

- 丸の半径は幅の半分。くびれは 35 度で丸から離れ、膨らみは半径の 8/30
- 印の移動(380ms、時間は直線)。前の端と後ろの端が同じイージング `cubic-bezier(.7, 0, .4, 1)`(初動がゆっくり)で動き、後ろの端は時間の 20% 遅れて動き出す(`gourd.switchEasing`、`gourd.trail`)
- 伸び(前と後ろの差)は、隣へ移るときの最大までに抑える。2つ以上離れた移動では、伸びきったあとは同じ長さのまま進む
- `bouncy = true`(既定は false)で弾みを付ける。時間は 560ms(`gourd.bounceDuration`)で、前と後ろの端を次の区切りでなめらかにつなぐ(D は移動距離)

| 端 | 0 | .2 | .4 | .55 | .72 | .75 | .88 | 1 |
|---|---|---|---|---|---|---|---|---|
| 前 | 0 | -4dp(縮んで後ろへためる) | - | D + 5dp(通り過ぎる) | - | D - 1.5dp | - | D |
| 後ろ | 0 | -1dp | -1dp | - | D + 4dp(追いついて縮む) | - | D - 1dp | D |

- 幅はボタンの大きさ × (ボタンの大きさ / 長さ)^.25(.7〜1.08 倍)。伸びると細く、縮むと太る
- 形は、両端が丸い棒と、ひょうたんの内側の輪郭(縁から 4dp)のなめらかな小さいほう。くびれを通るところが凹む。くびれに合わせる強さは、始めと終わりの .12 で 0 から 1 へ
- 行き先のアイコンの色は、時間の 55% で変わる
- 印の形は毎コマ作り直す(内側の影が形を覚えるため、形が変わったら作り直しが要る)

- 継ぎ目(bridge)の伸びと角の丸みの区切りは参照実装と同じ(閉じる: 縮み始め .4、丸め終わり .65 / 開く: 伸び終わり .6、角が戻る .35〜.9)
- 継ぎ目の上端と下端は、その時点のパネルの行き先側の辺に合わせる(縮むパネルから継ぎ目がはみ出さないように)
- パネルがある間は、継ぎ目の先をパネルの角の丸みの終わりまで必ず届かせ、継ぎ目の角の丸みはパネルに重なる分だけにする(継ぎ目とパネルの間に隙間を作らない)
- パネルの中身は、ひょうたんの形を切り抜いて描く(開閉中に縮んだ中身が、ひょうたんの前に出ないように)
- フィレットは時間では決めず、その時点のパネルの行き先側の辺に付ける。大きさは、辺の残りの長さ、辺とひょうたんの中心の間、継ぎ目の重なりに合わせて縮む(参照実装は時間で出し入れする)

## 向き

| 部品 | 決め方 |
|---|---|
| `GourdTabRail` | 縦向きで計算した輪郭と印の形を、縦横を入れ替えて横向きにする |
| `GourdRailPanel` | ひょうたん、継ぎ目、フィレット、パネル(ジニーの変形も含む)のすべてを「左に縦のひょうたん、右にパネル」の向きで計算し、`side` に合わせて写す(右: 左右反転、上: 縦横の入れ替え、下: 縦横の入れ替え + 上下反転)。左右なら縦、上下なら横のひょうたん |

- `railAlignment = GourdAlignment(bias)`。bias は -1 で先頭(上か左、`Start`、既定)、0 で真ん中(`Center`)、1 で末尾(下か右、`End`)。間の値も使える
- フィレットは、ひょうたんとパネルの端の間に余りがある側に入れる。先頭に寄せると下だけ、末尾に寄せると上だけ、間なら両方
- 余りがパネルの角の丸みとフィレットの合計(16 + 12dp)より狭いときは、角とフィレットの横の丸みはそのままで、縦の丸みだけを余りに合わせて縮める(ゆるい S 字の段になる)。端にぴったりなら、角は継ぎ目に隠れる
- `panelSize` は、ひょうたんから離れる向きのパネルの大きさ(左右なら幅、上下なら高さ)。省くと残りいっぱい

## 印の動きの共有

`rememberIndicatorMotion(index, duration, easing)` を `PiyoTabs` とひょうたんで共有する。どちらも「どこから・どこへ・どこまで進んだか」だけを持ち、`PiyoTabs` はそのまま滑らせ、ひょうたんは上の表で伸び縮みさせる(ひょうたんは時間を直線のまま使う)。

## 動きを減らす

`PiyoTheme(reduceMotion = ...)`。既定は端末の「アニメーションを削除」(`ANIMATOR_DURATION_SCALE == 0`)。true のときは、ジニー、継ぎ目、印、押下の動き、色の変化をアニメーションなしで切り替える。

## 重さへの対策

1コマを、組み立て(UI スレッド)と描画命令の送り出し(RenderThread)に分けて測ると、開閉で重いのは RenderThread 側だった(GPU そのものは 1コマ 6ms 前後)。要素を1つずつ外して測り、効いたものから直した。

| 問題 | 対策 |
|---|---|
| `BlurMaskFilter` は形が変わるたびに CPU でぼかしを作り直し、開閉中に1コマ 24ms 以上かかった | 線状の影と外の影を、太さ・濃さの違う線や形を3枚重ねた近似にした |
| ひょうたん + 継ぎ目 + パネルの合成(`Path.op`)を、1コマに何度も作っていた | `JoinShape` で、同じ大きさと状態なら輪郭を使い回す |
| 開閉の値をコンポーズで読み、毎コマ組み直していた | 形・クリップ・印の位置は描画とレイアウトの段階で読む |
| 枠のスイープグラデーション(14色)を、毎コマ上下2回作って大きな線に使っていた。開閉の遅れの約半分 | 面の大きさの画像に一度だけ描き(上下で継ぎ目を変える処理もこのとき済ませる)、枠はその画像を色にして1回で描く。大きさが変わらない間は使い回す(画素数の上限つき) |
| 印の内側の影(Compose の `innerShadow`)を、形が変わるたびに作り直していた。切り替えの遅れの約4割 | 毎コマ形が変わる形(`PiyoChangingShape`。印、ジニーの面)だけ、ずらした向きの縁から内へ薄れるグラデーションで塗る近似にした。切り抜きは使わない。印は止まっているときも同じ描き方にし、動き始めと終わりで見た目が跳ねないようにした |

効かなかったもの(戻した): 枠を輪郭で切り抜く処理をやめる、塗りを使い回すだけ(画像にしない)、内側の影を輪郭で切り抜いて線を重ねる近似。

実機(CPH2199、60Hz、リリースビルド)で、20回ずつ測った遅れたコマの割合:

| 操作 | 対策前 | 対策後 |
|---|---|---|
| ひょうたんとパネルの開閉 | 19.5〜22% | 10〜16% |
| ひょうたんの切り替え | 19.2% | 8.5〜9.8% |

残りの重さの一部は線状の影(3本重ね。外すと開閉が約3ポイント下がる)。見た目に関わるので残している。

## 参照実装との違い

| 違い | 理由 |
|---|---|
| 開閉の間も、パネルとひょうたんを1つの形にまとめて描く | Glass は縁を描くので、別々に描くと継ぎ目に線が出る。このため、閉じ終わりのパネルは薄れずにひょうたんへ吸い込まれる(中身は参照実装どおり薄れる) |
| ジニーの角を円弧にした | 進行度 0 で角丸の四角と一致させるため |
| 印の動き(初動がゆっくり、伸びの上限、くびれで凹む、弾みはオプション) | 動きを詰めた結果。参照実装は縦に伸びるだけ |
| パネルの影 | 参照実装は全体に `drop-shadow` をかける。こちらは現在のスタイルの `Card` の面(線状の影)を使う |
